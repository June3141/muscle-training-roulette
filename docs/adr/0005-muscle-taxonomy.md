# ADR 0005: 筋肉タキソノミーを 22 分類で確定する

- ステータス: **Accepted**
- 日付: 2026-08-17
- 関連: design.md §4.3, §2 Q1

## 背景

design.md §4.3 は 22 分類を挙げている。既存データセットより細かいのは意図的で、
**この粒度がないと Q1（特に効く部位を表現できるか）を検証できない**（サイドレイズと
ショルダープレスが同じ場所を光らせてしまう）。

一方、上流データを実測すると、**22 分類のうちいくつかは実データ上で機能しない疑いがある。**
分類を持つこと自体にコストはないが、**常に同じ値が入る分類は情報を持たず、
可視化の目盛りを無駄に細かくするだけ**なので、確定させておく必要がある。

数値の出典は `docs/data-survey.md`。

## 決定

**22 分類。** §4.3 の 22 分類から菱形筋を統合し、前腕屈筋群を足した。

| 分類 | 判断 | 根拠 |
|---|---|---|
| **菱形筋** | **僧帽筋中下部に統合** | `middle back` 関連 73 件のうち、肩甲骨内転を主目的と読める種目名は **5 件のみ**。判別材料がなく、分けても常に同じ値になる |
| **首** | **対象外（明示的に捨てる）** | 上流に 5 件あるが、**secondary 参照が 0**。他のどの種目とも繋がっていない孤島 |
| 中臀筋 | 維持。M1 で自前で振る | 上流は 5 件しか持たないが、解剖学的にスクワット・ランジ・片脚種目で確実に働く |
| 内転筋 | 同上 | 6 件。ワイドスクワット / スモウ / サイドランジに振る |
| 腹横筋 | 維持。ただし人体図には出さない | Plank / Ab Rollout / Pallof Press / Dead Bug など**アンチ伸展系 10 件が判別できる**。深層筋なので図に描けず、バーチャート専用 |
| **前腕屈筋群** | **追加** | §4.3 は前腕を腕橈骨筋しか持たないが、腕橈骨筋は**肘屈曲筋**。デッドリフトやプルアップの「握力」を表現できず、**97 件が写る先を失う**（握力補助 76 + 手関節 21） |
| ローテーターカフ | **分類を足さず、5 件を `selectable: false`** | 純粋なローテーターカフ種目は 5 件のみ。深層筋で人体図に描けず、分類を足しても目盛りが増えるだけ。データには残す |
| 腹斜筋 | 維持 | 回旋・側屈系 14 件で判別できる |

## 理由

### 分類を削る基準は「判別できるか」

菱形筋と首は、削る理由が違う。

- **菱形筋**は、データはある（`middle back` 73 件）が **僧帽筋中下部と区別する手がかりがない**。
  分けると 2 つの分類に常に同じ値が入り、可視化の情報量が増えないまま目盛りだけ増える
- **首**は、そもそも他種目と繋がっていない。5 件の首トレ専用種目だけが持つ分類になり、
  部位選択に出しても「首」を選んだ人にしか意味がない

### 中臀筋を「上流にないから消す」としない理由

§11 でこのデータセット自体を資産と位置づけている。
**既存データセットが持っていない情報を足すことが価値**であって、
上流に合わせて削るのは目的と逆行する。

振る作業も片脚種目とスクワット系に限れば機械的ルールで済み、全件手作業にはならない。

## 影響

- `packages/data/src/taxonomy.ts` が 22 分類になる
- M1 の写像作業から菱形筋の分離が消える（Issue「背中を 5 分類に写像する」→ 4 分類）
- M1 に「中臀筋・内転筋を他種目の secondary から振る」作業が加わる
- **M4 の人体図は 22 分類すべてを描けない。** 腹横筋は深層筋なので、
  人体図とバーチャートで表示できる分類が異なる（ADR 0003 の論点に合流する）

## 未解決

- 中臀筋・内転筋に振る**比率**は M2 の重み生成で決める。どの種目に振るかは決定済み
  （片脚支持 / ワイドスタンス / 前額面の動作。`pipeline/mapping/hip-stabilizers.ts`）
- 前腕屈筋群を部位選択 UI に出すかは M4 で決める。腕橈骨筋と統合表示でもよい
