# ADR 0003: 筋肉タキソノミーの粒度と人体図 SVG の粒度衝突

- ステータス: **Draft**（M1 で決定する）
- 日付: 2026-08-17
- 関連: design.md §4.3, §8.2

## 背景

本プロジェクトのタキソノミー（§4.3）は既存データセットより細かい。

- 三角筋 → 前部 / 中部 / 後部
- 大胸筋 → 上部（鎖骨部）/ 中下部（胸肋部）

一方、流用候補の SVG（`lahaxearnaud/body-highlighter` 系、いずれも
`HichamELBSI/react-native-body-highlighter` のパスを祖先に持つ）は
`chest` / `front-deltoids` / `back-deltoids` 程度の粒度しか持たず、
**三角筋中部と大胸筋の上下分割がない。**

分割しない場合、サイドレイズとショルダープレスが同じ場所を光らせることになり、
Q1（重み付けデータは「特に効く部位」を表現できるか）の検証力が落ちる。
可視化は Q1 の主計測器（§2）なので、これは計測器の分解能の問題である。

## 選択肢

| 案  | 内容                                       | コスト                   | Q1 への影響                                      |
| --- | ------------------------------------------ | ------------------------ | ------------------------------------------------ |
| A   | SVG のパスを自前で分割する                 | 高（ベジエの手作業分割） | 分解能を保てる                                   |
| B   | SVG の粒度に合わせてタキソノミーを粗くする | 低                       | Q1 の検証が成立しなくなる                        |
| C   | データは細かいまま、SVG 表示時に合算する   | 低                       | 図では区別できないが、バーチャートでは区別できる |
| D   | 人体図をやめてバーチャートのみにする       | 最低                     | 分解能は保てるが、部位の直感的な把握を失う       |

## 現時点の傾向

**三角筋は A（SVG のパスを分割）を前提にする。大胸筋上下は C で始める。**

三角筋を分けたい理由は Q1 の検証力そのもの。M1 の写像を実装した結果、
**317 件を前部 219 / 中部 166 / 後部 69 に振り分けられた**（重複あり）。
これだけの分解能をデータ側が持っているのに、図で合算すると
サイドレイズとショルダープレスが同じ場所を光らせることになり、
**計測器の分解能がデータより粗い**状態になる。

大胸筋の上部/中下部は、まず C（表示時に合算）で始めてよい。
インクライン系とフラット系の違いは種目名から明らかなので、
図で区別できなくてもバーチャートで読める。

データ側のタキソノミーを粗くする（B）のは不可逆な損失なので採らない。

## 決定を保留する理由

M1 の時点では、どの筋肉が SVG のどのパスに対応するかのマッピング表がまだない。
マッピングを作る過程で、衝突する箇所が §4.3 の警告より多いのか少ないのかが分かる。
それを見てから決める。

## 参考

流用元はいずれも MIT。**ライブラリとして依存せず、SVG パスだけ抽出して自前アセットにできる。**
これは §8 の「画像素材を使わず SVG を自前で持つ」判断と矛盾しない。
