# ADR 0001: 片手/両手の重量正規化ルール

- ステータス: **Proposed**（M0 で確定させる）
- 日付: 2026-08-17
- 関連: design.md §4.5

## 背景

ダンベル片手 20kg を `20` と持つか `40` と持つか。
負荷を「片側」で保持するか「合計」で保持するかはスキーマの根幹であり、
後から変えると全データを書き直すことになる。

現時点では v1 に重量入力の UI は存在しない（§3「作らない」に記録・保存が含まれる）。
それでもここで決めるのは、**将来のトレーニングアプリのコア資産としてデータセットを作る**（§1）以上、
`lateralityOptions` を持つスキーマが「片側の値」を意味するのか「合計」を意味するのかを
未定義のまま 800 件に書き込むと、後で全件の意味が変わるため。

## 決定（案）

**片側（per-side）で保持し、表示時に合計へ変換する。**

- 保持する値: 片手が扱う重量。ダンベル片手 20kg → `20`
- バーベル等の bilateral 種目: 器具全体の重量をそのまま保持する（片側 10kg × 2 ではなく `20`）
- 表示: unilateral 種目には「片側」と明示する。合計表示が必要なら UI 層で `× 2` する

### なぜ片側か

1. ユーザーが器具から読み取る値がそのまま入る。ダンベルには「20」と書いてある
2. unilateral / bilateral を切り替えたとき（§4.2 の `lateralityOptions`）、
   片側保持なら値の意味が変わらない。合計保持だと切り替えのたびに 2 倍/半分の変換が必要になる
3. 左右で重量を変える（怪我のリハビリ等）将来の拡張が、スキーマ変更なしに載る

### なぜ bilateral は「合計」なのか（一貫していないように見える件）

バーベルは物理的に 1 つの器具であり「片側」が存在しない。
つまりこのルールは「**器具 1 個あたりの重量を持つ**」と言い換えられる。
ダンベルは 2 個使うので 1 個あたり、バーベルは 1 個なので全体。この言い換えなら例外はない。

## 影響

- スキーマに `loadUnit: "per_implement"` を定数として記録し、意味を明文化する
- 重量入力 UI を作る段階（v1 のスコープ外）で、unilateral 種目には片側表記のラベルを必須にする

## 未解決

- ケーブル / マシンのスタック表示は片側でも合計でもなく「スタックのピン位置」であり、
  この規則に乗らない。v1 では扱わないが、`loadUnit` を種目ごとに上書きできる余地は残す
