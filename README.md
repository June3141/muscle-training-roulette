# muscle-training-roulette

部位を選ぶと、その部位をカバーする種目セットを提案する静的サイト。
ユーザーデータを一切保持せず、出力のみを行う。

> [!WARNING]
> **開発中です。まだ動きません。**
> 種目データの重み付けは未検証のドラフトであり、**現時点の値をそのまま使わないでください。**
> リリースタグはまだ切っていません。

## 本当の目的

サイトは成果物の本体ではない。**将来のトレーニングアプリのコアになる 2 つの資産を、
ユーザーもDBも認証も持たない状態で先に完成させる**のが目的。

1. 種目 × 筋肉の**重み付きデータセット**
2. 「指定部位を最もよくカバーする N 種目」を選ぶ**選択エンジン**

サイトはこの 2 つを目視検査するための計測器。

日本語名がついた種目データセットも、重み付き（連続値）のものも、器具軸が分離されたものも現存しない。
**サイトよりデータセットの方が資産価値が高い。**

### やらないこと

- 記録・保存・ログイン
- 需要検証（反応の有無から市場を推論しない）
- 回復度／筋肉痛の考慮

詳細は [design.md](./design.md) を参照。

## 構成

```
data/            データセット本体（成果物）。upstream/ は取得スクリプトで再現するのでコミットしない
packages/data/   筋肉タキソノミー、種目スキーマ、バリデーション
packages/engine/ 選択エンジン（重み付き最大被覆の貪欲法）とカバレッジ計算
apps/web/        サイト（M6）。現在はタキソノミーを表示するだけのプレースホルダ
docs/adr/        設計判断の記録
```

依存は `data → engine → web` の一方向。データパッケージ単体を切り出して公開できる状態を保ちます。

## 開発

```bash
corepack enable pnpm
pnpm install
pnpm verify     # format / lint / typecheck / test / 複雑度 / 未使用検出 / build
```

| コマンド | 内容 |
|---|---|
| `pnpm test` | テスト |
| `pnpm coverage` | カバレッジ（閾値を下回ると失敗） |
| `pnpm complexity` | 循環的複雑度・ネスト深さ・関数長 |
| `pnpm unused` | 未使用の export / 依存 |
| `pnpm data:fetch` | 上流データを `data/upstream/` に取得 |

ツール選定の理由は [docs/toolchain.md](./docs/toolchain.md)。

## 貢献

最も価値がある貢献は**重みデータの明らかな誤りの指摘**です。
重み付けには主観が入るため、**収束ではなく「明らかな誤りの除去」を目的に据えています。**

[CONTRIBUTING.md](./CONTRIBUTING.md) を読んでから Issue を立ててください。
